השמה אינה משוואה

B = B + 2·A: משמאל הערך החדש, מימין חישוב מהערכים הקודמים

מקור:דף הקריאה "ב.1": "נדון לרגע בצורת הכתיבה", ההערה על Java, ו"כדאי להיזכר כאן שוב" בדוגמה 4· ודאות בפענוח המקור: גבוהה
המורה שלך

אהקדמה

מה לומדים

נלמד לקרוא נכון שורה כמו B = B + 2·A. זו לא משוואה! היא אומרת: הערך החדש של B הוא B הקודם ועוד פעמיים A הקודם.

למה זה חשוב

מהמתמטיקה אנחנו רגילים לפתור משוואות. כאן זה מוביל לטעויות, כמו "B = B, נכון לכל B!". מי שקורא נכון מבין מה האלגוריתם עושה — וגם יבין בהמשך פקודות השמה בשפת Java.

בסוף השיעור תדעו
  • לקרוא ביטוי פלט: משמאל — פלט, מימין — חישוב על ערכי הקלט
  • להימנע מהצבה, מהעברת אגפים ומחיפוש פתרון
  • לקרוא את שורת ה־Java b = b + 2*a;

במילון מושגים

השמה

פעולה ששמה ערך חדש בתוך משתנה. מחשבים את אגף ימין, ואת התוצאה מכניסים למשתנה שמשמאל.

משוואה

במתמטיקה: טענה ששני הצדדים שווים, ומחפשים מספר שמקיים אותה. לא זה מה שכתוב כאן.

אגף שמאל

מה שכתוב לפני ה־"=". כאן זה תמיד הערך החדש (הפלט).

אגף ימין

מה שכתוב אחרי ה־"=". מחשבים אותו מהערכים שהיו קודם (הקלט).

Java

שפת תכנות. גם בה b = b + 2*a; היא השמה ולא משוואה.

נקודה־פסיק

הסימן ; שבסוף כל פקודה בשפת Java.

גהסבר ויזואלי

רמה: רגילהסבר חדש

כשמוחקים את הסימונים I ו־O מהתוצאה של דוגמה 1 מקבלים: A = 0, B = B + 2·A.

מהמתמטיקה מתפתים להציב את A = 0 בשורה השנייה ולקבל B = B. זה שגוי (במקור: ✗ אדום).

הקריאה הנכונה:

  • "A החדש שווה ל־0" (A המקורי יכול היה להיות 732).
  • "B החדש שווה ל־B המקורי ועוד פעמיים A המקורי" (הוספנו ל־B פעמיים 732, לא פעמיים 0).
חומר מקור

אנו רגילים מעולם המתמטיקה שכל שוויון שכזה הוא משוואה, וכל צמד ביטויים שכזה הוא מערכת משוואות, ולכן עשויים להתפתות לבצע מהלכים כגון להציב ערכי משוואה אחת במשוואה השניה, להעביר אגפים, לחפש פתרון או להכריז: "אין פתרון" / "קיימים אינסוף פתרונות", אולם הביטויים הללו אינם משוואות. ✗

חומר מקור

צורת הכתיבה הזו מתארת פלט (שמופיע משמאל) כתוצאה של חישוב כלשהו על ערכי הקלט (שמופיע מימין).

חומר מקור

הערה: צורת הכתיבה הזו תלווה אותנו גם בתיכנות ב-Java. בשפת Java נכתוב, למשל: b = b + 2*a; ובכך נתכוון, שערכו של המשתנה b בסיום הפעולה שווה לערכו של b בתחילת הפעולה ועוד פעמיים ערכו של המשתנה a בתחילת הפעולה. (...) פקודות בשפת java מסתיימות בסימון ; (נקודה-פסיק).

חומר מקור

כדאי להיזכר כאן שוב: הנטייה הטבעית שלנו למול צמד הביטויים: A=0 B=B+2A היא להציב אותם זה בזה, וכך לקבל B=B+2·0 ולכן B=B (ונכריז: נכון לכל B!) ✗

ההצבה הזו איננה קשורה לענייננו כלל. (...)

"A החדש שווה ל-0" (ייתכן ש-A המקורי היה 732, למשל – אבל החדש הוא 0).

"B החדש שווה ל-B המקורי ועוד פעמיים A המקורי" (לא הוספנו ל-B פעמיים 0, אלא הוספנו לו פעמיים 732).

חומר מקור

אלו מבין הקוראים שהתובנה הזו עדיין לא מיושבת אצלם, מתבקשים: לשחק באלגוריתם הזה עם מספרי קלט בולטים כמו 666, 42 וכדומה, ולחוש את השפעת המספרים הללו על התוצאה (ולהשוות לתווית הראשית המתוארת), להוסיף לתוויות בתרשים סימוני Input/Output שיכולים לשפר את ההבנה (...)

דהדגמה מפורקתחומר מקור

הטעות שהמרצה מזהירה מפניה — ואיך קוראים נכון

שלב 1 מתוך 6
1WHILE (A)
2   ADD (B)
3   ADD (B)
4   SUB (A)
5ENDW

התווית של הלולאה בדוגמה 4 היא: A = 0 ו־B = B + 2A.

ההתנסות

חשבו מראש לפי התווית B = B + 2·A: מה יהיה B בסוף אם A = 666 ו־B = 42? אחר כך הריצו ובדקו (יש 666 סיבובים — כדאי ללחוץ "עד הסוף"). נסו גם מספרים משלכם.

ושאלה לבדיקת ההבנה

בחירהרמה 2תרגיל חדש

לקטע קוד יש התווית A = 0, B = B + 2·A. לפני הקטע A = 5 ו־B = 3. מה ערכו של B אחרי הקטע?

חסיכום והמשך

מה למדנו
  • B = B + 2·A היא השמה: משמאל הערך החדש, מימין חישוב מהערכים הקודמים
  • לא מציבים ביטוי בביטוי, לא מעבירים אגפים ולא מחפשים פתרון
  • כדאי לבדוק עם מספרים בולטים, כמו 666 ו־42, כדי להרגיש את המשמעות
  • ב־Java זה נכתב b = b + 2*a;, וכל פקודה מסתיימת ב־;

מושגים שכבר למדתם בקורס: 0. שיעורים שהושלמו: 0.

מה הלאה

עכשיו, כשאנחנו קוראים תוויות נכון, נכיר את הכלי השני לניתוח: התרשים — תוויות ליד חלקי הקוד, שמשורשרות לתווית ראשית.
